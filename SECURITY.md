# Security Policy — Factory Frenzy PC Multiplayer

## Scope

This policy covers the **Factory Frenzy PC Multiplayer** Unity project, including Netcode for GameObjects, lobby and race logic, player interactions, and import of levels exported by the VR Editor.

This is a student project. No formal security-support period or public vulnerability-response service has been established.

## Reporting a vulnerability

**Do not disclose exploitable details in a public GitHub issue.** Contact the repository maintainers privately using GitHub's **Report a vulnerability** feature, if enabled, or a private team-approved channel.

Provide:

- The affected feature and potential impact.
- Clear reproduction steps, including host/client roles and number of players.
- Unity and Netcode package versions.
- Relevant logs or a minimal proof of concept with credentials and personal information removed.

Maintainers should triage reports and coordinate fixes before public disclosure. **No guaranteed response or remediation time is promised.**

## Security practices

### Multiplayer and networking

- Treat all client-supplied requests as untrusted, even when clients use the official game build.
- Validate requests on the server before changing race state, checkpoints, rankings, spawn positions, or player state.
- Verify the requesting client's ownership or authorization for player-specific actions.
- Keep race start, finish order, countdown, and authoritative game-state decisions on the server.
- Limit repeated or invalid requests where appropriate; never rely on UI controls alone to prevent abuse.
- Do not expose service credentials, relay keys, or private session data in logs or source control.
- Test networking changes with a host and at least one separate client.

### JSON level import

- Treat imported JSON as untrusted input, including files generated by the VR Editor.
- Validate the expected schema and allowlisted element types before instantiating objects.
- Check file size, object count, numeric ranges, transforms, and required fields.
- Reject invalid, non-finite, or extreme values that could crash or freeze the game.
- Restrict level file selection to intended locations and prevent path traversal.
- Never execute code or arbitrary commands based on level-file content.
- Coordinate schema changes with the VR Editor team.

### Unity and repository hygiene

- Use trusted Unity packages and assets; review dependency changes.
- Do not commit passwords, API tokens, private keys, or machine-specific secrets.
- Exclude generated Unity directories such as `Library/`, `Temp/`, and `Logs/` from Git.
- Review pull requests touching RPCs, authentication, file I/O, serialization, or lobby configuration.
- Revoke or rotate exposed secrets immediately.

## Before release or demonstration

- [ ] Verify unauthorized clients cannot alter other players' state.
- [ ] Verify the server controls countdown, checkpoint, respawn, and finish results.
- [ ] Test malformed, oversized, and unexpected JSON level files.
- [ ] Test lobby behavior with multiple clients and unexpected disconnects.
- [ ] Confirm no credentials or sensitive data are included in the repository or build logs.
- [ ] Verify compatibility with the VR Editor's agreed JSON format.
